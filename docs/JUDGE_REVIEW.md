# CouncilMed: Technical Review & Hackathon Judge Guide

## The Problem
In modern medical AI, systems are typically monolithic: a single neural network makes a prediction. If that model encounters out-of-distribution data or suffers from a silent failure, it outputs a highly confident, incorrect diagnosis. For clinicians, this "black box" single-point-of-failure is unacceptable.

## The Solution: CouncilMed
CouncilMed is an offline-first, local medical workstation that implements a **"Council" of AI models**. Instead of relying on one model, an image is processed concurrently by multiple distinct architectures (e.g., DenseNet, ResNet+Attention, U-Net). 

### Core Innovation: Entropy-Weighted Fusion
The system does not simply average the votes. It calculates the **Shannon entropy** of each model's probability distribution to measure "sharpness" (confidence). Models that are uncertain (high entropy) are mathematically down-weighted. The system then factors in the historical calibration (Expected Calibration Error) of each model.

This means if Model A is 99% confident, and Model B is guessing (33/33/33), Model B's vote is almost entirely discarded, protecting the consensus.

## Technical Architecture Highlights
1. **Strict Vision/Language Separation**: PyTorch handles the mathematical inference. An Ollama LLM handles the clinical reasoning. The LLM *never* sees the image, preventing visual hallucinations. The LLM grounds its reasoning exclusively on the math generated by the PyTorch Council and clinical guidelines retrieved via ChromaDB (RAG).
2. **Local-First & Private**: Built on a Tauri/React frontend and FastAPI/SQLite backend. 100% of the inference (PyTorch and Ollama) runs locally. Zero PHI (Protected Health Information) is sent to the cloud.
3. **Traceability**: Every individual model's prediction, confidence, processing time, and Grad-CAM heatmap is explicitly shown to the doctor.

## Why it Wins
CouncilMed moves beyond the toy problem of "I trained an image classifier." It tackles the actual engineering challenges of deploying medical AI:
- How do we handle model disagreement?
- How do we explain the math to a doctor in English?
- How do we guarantee patient data privacy?
- How do we maintain an immutable audit trail?

## Current Limitations
- The provided repository utilizes structural PyTorch models with random initializations for demonstration purposes. To use it in a clinical setting, the models in the `model_registry` must be updated with weights trained on real medical datasets.
- DICOM parsing is partially implemented; standard formats (JPEG/PNG) are fully supported.
