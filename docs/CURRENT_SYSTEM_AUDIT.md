# CouncilMed — Current System Audit

> **Audit Date:** 2026-08-10
> **Auditor:** CouncilMed Rebuild Team
> **Repository:** https://github.com/iamnih4l/CouncilMed
> **Verdict:** The repository contains significant architectural scaffolding and a visually polished UI, but the core inference pipeline is **fundamentally simulated**. None of the three "Council members" perform genuine model inference — all diagnostic outputs are derived from pixel heuristics and `Math.random()`. The system cannot be trusted for any clinical interpretation.

## Component-by-Component Analysis

---

### 1. DenseNet-121 Classifier

**File:** `src/services/inference/models/DenseNet121.ts`

**Status: SIMULATED**

The `buildDenseNet121()` function attempts to load a TF.js graph model from `/models/classifier/model.json`. A trained MobileNetV2 model (~10MB TF.js weights) **does exist** at `public/models/classifier/`. However, the `runDenseNet121Inference()` function **completely ignores the loaded model**:

```typescript
// Line 69: The model parameter is prefixed with underscore — it is UNUSED
export async function runDenseNet121Inference(
  _model: tf.GraphModel | tf.LayersModel,  // NEVER USED
```

Instead of running the model, the function:
1. Calls `analyzeImageHeuristics()` to compute basic pixel statistics
2. Uses `Math.random()` to generate fake probability distributions
3. Returns fabricated classifications based on whether a "bright spot" is detected

**Trained Model Exists:** Yes — `training/output/classifier/classifier.keras` (28MB, MobileNetV2, trained on Brain Tumor MRI 4-class dataset). The TF.js export exists at `public/models/classifier/` (~10MB shards). However, it is **loaded but never called for inference**.

**Verdict:** The trained model weights are present but completely bypassed. The inference is 100% heuristic + random noise.

---

### 2. Attention-Net (Localization)

**File:** `src/services/inference/models/AttentionNet.ts`

**Status: SIMULATED**

The `buildAttentionNet()` function constructs a CBAM-based encoder architecture in TF.js from scratch. The model architecture is structurally sound, but the weights are **randomly initialized** — there are no pretrained weights loaded.

The `runAttentionNetInference()` function again ignores the model (`_model` parameter unused). The "attention heatmap" is generated by resizing the input image to 14x14 and computing the average across RGB channels. This produces a **downsampled grayscale version of the input**, not learned attention. The confidence is fabricated:

```typescript
const confidence = stats.isAbnormal ? 80 + (Math.random() * 15) : 10 + (Math.random() * 20);
```

**Trained Model Exists:** A TF.js model exists at `public/models/attention/` (~9.7MB). It is loaded but never used for inference.

**Verdict:** Architecture is valid as scaffolding. Inference is 100% fabricated. The "heatmap" is just a blurred version of the input image.

---

### 3. Swin-UNETR (Segmentation)

**File:** `src/services/inference/models/SwinUNETR.ts`

**Status: SIMULATED**

The `buildSwinUNETR()` function constructs a simplified Swin Transformer architecture in TF.js. This is an approximation (dense layers instead of windowed attention), and the weights are **randomly initialized**.

The `runSwinUNETRInference()` function ignores the model entirely. The "segmentation mask" is generated by:
1. Resizing the input to 8x8
2. Computing grayscale
3. **Extruding the 2D image into a fake 3D volume** with depth-weighted falloff
4. Calculating fake tumor volume: `solidVoxels * 15.6` (arbitrary multiplier)

The segmented regions have hardcoded labels with computed-from-random percentages.

**Verdict:** The "3D segmentation" is a 2D image extruded to fake depth. No actual volumetric analysis occurs.

### 4. Image Heuristics Engine

**File:** `src/services/inference/ImageHeuristics.ts`

**Status: PARTIALLY FUNCTIONAL**

This module performs genuine pixel analysis (mean intensity, variance, bright spot detection, center-of-mass calculation). It correctly identifies abnormal bright regions in grayscale images. However, it is used as a **substitute for real model inference**, not as a preprocessing or quality gate.

### 5. Council Consensus Algorithm

**File:** `src/services/inference/CouncilConsensus.ts`

**Status: PARTIALLY FUNCTIONAL (on simulated data)**

The consensus logic is structurally reasonable:
- Weighted fusion: 40% DenseNet, 30% Attention, 30% Swin
- Spatial agreement computed from Euclidean distance
- Clinical notes generation based on model outputs
- Model agreement scoring

**However:** All inputs are simulated, making the fusion meaningless. The 40/30/30 weights have no scientific justification. No uncertainty quantification beyond simple thresholds. No calibration.

## What Actually Works

1. **Training pipeline** — MobileNetV2 classifier genuinely trained on Brain Tumor MRI data
2. **TF.js model export** — Models correctly converted and deployed to `public/models/`
3. **Model loading** — Inference worker correctly loads TF.js models into memory
4. **DICOM parsing** — Basic single-frame DICOM parsing works
5. **UI framework** — Component architecture, routing, animations, styling are solid
6. **Web Worker** — Non-blocking inference pipeline correctly implemented
7. **LangGraph flow** — Agent orchestration graph structure is correct
8. **Report structure** — RSNA-style report generation with proper clinical guardrails
9. **PDF export** — Functional PDF generation

1. **No real model inference** — All three models are loaded but never called
2. **No Grad-CAM** — Zero gradient-based explainability
3. **No genuine segmentation** — Fake 3D masks from 2D extrusion
4. **No desktop application** — Web-only
5. **No medical image viewer** — No MPR, no window/level, no measurements
6. **No case management** — No persistent patient/study workflow
7. **No model registry** — No validation metrics, versioning, or documentation
8. **No audit trail** — No decision lineage
9. **No security** — Open CORS, no auth, no input validation
10. **No multi-modality support** — Hardcoded to MRI brain tumors
11. **No human-in-the-loop** — No accept/reject/edit workflow
12. **No uncertainty quantification** — Random numbers have no meaningful uncertainty
